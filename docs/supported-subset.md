# The supported subset

Pudding reads only the code a law reaches. A module may contain anything else.

A law over code outside the subset is refused, with the reason, at the exact
expression. A refused law is executed instead and reported as *checked* or
*sampled*, so a law can always be written and gets promoted to *proved* when
the subset grows.

## What can be proved

- **Values:** `boolean`, `bigint`, `string`, whole `number`s, `null`, `undefined`, object literals, array literals and tuples, functions, `Map` and `Set`.
- **Operators:** `===` `!==` `!` `?:`; `&&`, `||` and `??`, which give one of their two sides as JavaScript does (`??` and `?.` trigger on both `null` and `undefined`); `?.`; `typeof`, `in`, unary `+`; `+ - * % < <= > >=` on bigint and number; `**` with a known non-negative integer exponent (up to 64 on literals, 8 on unknowns); `/` on bigint; string `+` and template literals (interpolating strings, bigints, numbers, booleans, `null` and `undefined`).
- **Conditions:** any value, as JavaScript takes it: `false`, zero, the empty string, `null` and `undefined` are false, and every object, array and function is true.
- **Null and undefined:** a property that an object does not have, a position outside an array and a parameter the call leaves out all read as `undefined`. Parameter and destructuring defaults trigger only on `undefined`, not `null`; `??` and `?.` handle both. A lookup by a key that is not known where it is used gives `undefined` for a miss when its type allows that, as for `Record<string, T | undefined>`; where the type says the key is always there, a miss must be proved impossible. Reading a property of `null` or `undefined`, or calling either, is a throw, and like any throw it must be proved unreachable (or checked with `expect(() => ...).toThrow()`).
- **Statements:** `const` and `let`, destructuring with defaults and rest patterns, assignment and `+=`-style updates of local variables, of properties and of array positions, `if`/`else`, `switch`, `try`/`catch` (without `finally`, destructuring or reading the caught error, mixed return and fallthrough inside `try`, or outer mutations inside `try`), `for…of` over an array of known length, a `Map` or a `Set`, `for`, `while` and `do` loops whose condition is settled at each round, `break`, `continue`, `return`, `throw`.
- **Functions:** declarations and arrows, in any module of the project, with defaults, destructured parameters, rest parameters (`...args`) and spread call arguments (`fn(...xs)`, `Math.min(...xs)`). A function may read and assign a variable of a function that encloses it, while that function is still running: a callback of `.map` can keep a running total.
- **Data:** module-level `const` tables and constant `enum`s (numeric, string and `const enum`), indexed by a key whose type guarantees it is present; conditional and nullish object spreads (`{ ...(cond ? a : null) }`); symbolic array indexing (`arr[i]` and `arr.at(i)`) on fixed-length arrays up to 64 elements; `.includes`, `.indexOf`, `.lastIndexOf`, `.some`, `.every`, `.find`, `.findIndex`, `.findLast`, `.findLastIndex`, `.map`, `.filter`, `.flatMap`, `.flat` (including `Infinity`), `.reduce`, `.reduceRight` (with or without an initial value), `.forEach`, `.concat`, `.join`, `.at`, `.slice`, `.with`, `.toSpliced`, `.reverse`, `.toReversed`, `.push`, `.pop`, `.shift`, `.unshift` and `.length` on arrays of known length; `.sort` and `.toSorted` with a comparing function; `Array.isArray`, `Array.from` of a list, a `Map`, a `Set` or `{ length }`; `Object.keys`, `Object.values`, `Object.entries` (on objects with a fixed property order), `Object.hasOwn`, `Object.fromEntries`, `Object.freeze` and `Object.assign`.
- **Maps and Sets:** `new Map` and `new Set`, empty or from a list, with booleans, numbers, bigints and strings as keys; `.get`, `.set`, `.add`, `.has`, `.delete`, `.clear`, `.forEach`, `.keys`, `.values`, `.entries`, `.size`, and ES2025 `Set` methods (`.union`, `.intersection`, `.difference`, `.symmetricDifference`, `.isSubsetOf`, `.isSupersetOf`, `.isDisjointFrom`); looping over one and spreading it.
- **Changes in place:** `total.sum += x`, `list[0] = x`, `list.push(x)`, `list.pop()`, `list.shift()`, `list.unshift(x)`, `list.reverse()`, `list.sort(compare)` and `Map`/`Set` `.set`/`.add`/`.delete`/`.clear` on an object, array or collection that the code under the law created itself. Two names for one object see each other's changes, a function changes what it is given, and a change behind a condition or an early return happens only on that path, all as in JavaScript.
- **Numbers and conversions:** `Math.floor`, `ceil`, `trunc` and `round` of a quotient or a value, `Math.abs`, `sign`, `min`, `max` (including `Infinity` and `-Infinity`) and `pow` (with a known non-negative integer exponent); `Number.isInteger`, `Number.isFinite`, `Number.isNaN`, `Number.isSafeInteger`, `Number.MAX_SAFE_INTEGER`, `Number.MIN_SAFE_INTEGER`; `String`, `Number`, `BigInt` and `Boolean` conversions. `Infinity` and `-Infinity` where they are compared with a number or passed to `Math.min`/`max`, as in `end ?? Infinity`.
- **Text:** `.padStart` and `.padEnd` to a known length, on a string known where it is used or on the text of a whole number, as in `String(cents % 100n).padStart(2, "0")`. On strings whose value is known where they are used (such as literals and finite string unions): `.slice`, `.substring`, `.charAt`, `.at`, `.codePointAt`, `.indexOf`, `.lastIndexOf`, `.startsWith`, `.endsWith`, `.includes`, `.trim`, `.trimStart`, `.trimEnd`, `.toUpperCase`, `.toLowerCase`, `.repeat`, `.split`, `.replace` and `.replaceAll` (with string arguments, not RegExp). On symbolic strings, `.startsWith`, `.endsWith` and `.includes` also settle statically when the prefix, suffix or literal fragment is fixed.
- **Matchers:** `expect(a)` supports `.toEqual`, `.toBe`, `.toBeGreaterThan`, `.toBeGreaterThanOrEqual`, `.toBeLessThan`, `.toBeLessThanOrEqual`, `.toBeUndefined`, `.toBeDefined`, `.toBeNull`, `.toBeTruthy`, `.toBeFalsy`, `.toHaveLength`, `.toContain`, `.toThrow` and their `.not` forms.

## What is refused

- fractions and plain `number` division;
- changing in place an object the code did not just create: one of the law's inputs, a module constant, something a `describe` shares between its laws, or the result of a condition choosing between two objects. Copy it first, as in `{ ...value }`;
- a change in place, or an assignment to a variable outside a callback, where JavaScript may skip it but a model must decide: on the right of `&&`, `||` or `??`, in a callback of `.some`, `.every`, `.find`, `.findIndex`, `.findLast`, `.findLastIndex`, `.sort` or `.toThrow`, and a `.push`, `.pop`, `.shift`, `.unshift`, `.set`, `.add`, `.delete` or `.clear` that changes length on only one side of a condition;
- adding a property to an object by assignment, or adding a property via `Object.assign` on only one side of a condition;
- sorting where the order depends on an input that has many values, a comparing function that does not order the elements consistently, and `.sort` without one;
- a function that uses a reassigned variable after the function that declared the variable has returned, such as a counter handed back by the function that made it;
- a function that uses the variable of a `for (let i = …)` loop around it, because JavaScript gives each round its own copy. Copy it into a `const` inside the loop;
- adding to a `Map` or a `Set` inside a loop over it, and a default in an array pattern that changes the list being taken apart;
- a property that every object inherits, such as `toString` read as a value, and objects as keys of a `Map` or a `Set`;
- reading a `const` or `let` before its declaration has run, and `__proto__`;
- an import such as `./x.js` when both `x.js` and `x.ts` exist, because TypeScript reads one and Node runs the other;
- `var`, loops whose length depends on an input, recursion, classes, async code, regular expressions and library calls.

## Limits worth knowing

- `Math.round` of a quotient is exact while the number divided stays strictly between -2^52 and 2^52, which each use must prove like any other bound.
- `.sort` and `.toSorted` take up to 64 elements, because every three of them are checked against each other. The comparing function may not assert or be able to throw: every pair is compared to check it, which is more than an engine compares.
- Law inputs are listed from their types, which needs `strictNullChecks`: without it a type does not say whether it holds `null` or `undefined`, and a law with a domain is not proved. Where laws are executed, it is run on the inputs the compiler still lists and reported as sampled.
- Each element of a `.filter` that may or may not pass, and each result of a `.flatMap` that depends on a condition, doubles the lists there could be. Up to 8 such elements are followed.
- Each optional property of an input, and each part of it that may be `null`, `undefined`, or a union alternative, multiplies the shapes the input can take. More than 64 shapes are refused, and so is an input type that refers to itself or has more than 10,000 parts.
- Consuming a `Map`, a `Set`, or one of their iterators (looping over it, `.forEach`, spreading it, or passing it to `Array.from`) needs to know which of its keys are equal. Creating an iterator with `.keys()`, `.values()` or `.entries()` and passing it around does not; keys that are inputs are also fine for `.get`, `.has`, `.delete`, `.size`, `.isSubsetOf`, `.isSupersetOf` and `.isDisjointFrom`.
- The compiler API Pudding uses is new in TypeScript 7 and changed between 7.0 and 7.1. Pudding is tested with `typescript` 7.0 and 7.1 and with `tsrs`; a later release may need a newer Pudding.
- Division by an unknown and products of two unknowns are outside `grind`'s arithmetic. Bound the divisor with a small `Integer<Min, Max>`, which is checked value by value, or [supply a proof](../README.md#supplying-a-proof). Large consecutive linear `Integer<Min, Max>` combinations (over 256 cases) are quantified symbolically for `grind` instead of enumerated.
- Symbolic strings support equality, concatenation and static affix checks; string methods that inspect or transform characters require a string whose value is known where it is used (such as a finite string union or literal).
- Repeated subexpressions are shared with `let`-bindings when printing Lean theorems, keeping loop-accumulated expressions compact; expressions whose printed size still exceeds the limit are refused instead of handed to Lean.
- Where a law is checked value by value, a string may grow to 500 characters. Past that Lean's kernel gives up, so the law is executed instead and reported as not proved.
- Prebuilt Lean downloads exist for macOS and Linux only.
